## 1. 定位

**品牌与口号**（详见 [brand.md](brand.md)）：**Pocketgrove** —— *Play in seconds. Make it yours in a sentence.*
（几秒就能玩，一句话变成你的。）点数单位为 Seeds。

**定位陈述**：对于想在碎片时间放松、偶尔也想"做点自己的东西"的成年休闲玩家，Pocketgrove 是一个**专做放置与经营类小游戏**的网页平台。和通用 AI 游戏生成器不同，它的每款游戏都有完整的存档、成长和离线收益，改一句话就能做出自己的版本，并分享给朋友比拼。

**为什么是放置与经营**
- 有存档和成长线 → 用户会回来，这是对手的薄弱点（通用生成器的游戏大多一次性）。
- 规则相对固定 → 可以用打磨好的题材模板保证质量下限，agent 主要改内容、数值和局部玩法，生成成功率和质量都更可控。
- 天然适合改编："把奶茶店换成猫咖""让升级更快"只需要改主题和数值。
- 修仙（cultivation）可以作为放置 RPG 的一个主题，而不是单独题材。

## 2. 用户画像

**主画像：Maya，27 岁，美国，市场助理**
- 通勤和午休刷手机；玩过 Cookie Clicker、Stardew Valley、各种 "tycoon" 小游戏。
- 不会编程，但喜欢个性化：换头像、做表情包、在 Canva 上做东西。
- 会在群聊里分享好玩的链接，也愿意为喜欢的工具每月付几美元。
- 痛点：手机游戏广告太多、要下载、要注册；想"做一个以我家猫为主角的小游戏"但不知道从哪开始。

**次画像：Leo，22 岁，大学生，Discord 社区活跃**
- 喜欢在群里比分、整活；会把好玩的东西改一改再发出去。
- 付费意愿低，但传播力强——主要贡献流量，不是收入。

## 3. 核心概念：编码 agent + 题材模板【已确定，2026-11-11 转向】

> 原方案「题材引擎为主」（AI 只写 `game.json`，由固定引擎运行）已被取代。完整设计见 [architecture.md](architecture.md)。

生成器是一个**编码 agent**（基于 Pi SDK，移植 ohmygame 的试玩工具和画板模型，只接 Claude），在服务端隔离容器里直接写游戏代码（TypeScript；2D 用 Phaser，3D 用 three.js），自己构建、试玩、修复。

| 层 | 谁负责 | 内容 |
|---|---|---|
| 共享运行时 | 我们（锁定，agent 不能改） | 固定步长循环、带种子的随机数、存档、服务器时间、离线收益、激励广告、挑战局和赛季接口、平台适配器 |
| 题材模板 | 我们（手工打磨，可用 studio / ohmygame 精修） | 每个题材一套完整可玩的项目：玩法、存档、转生、成就、挑战局、界面 |
| 游戏代码与配置 | AI（agent） | 在模板上改玩法、数值（`game.config.json`）、文案、界面；也可以从 2D 或 3D 起步工程写任意玩法 |
| 美术与媒体 | AI（媒体路由） | 图标、角色、背景；3D 模型、绑骨、动画；音效、音乐、配音；短视频（风格统一，素材可派生） |

**好处**：玩法不受引擎限制（"我想做一个赛车游戏"也能试）；模板保证质量下限和题材专精的手感。
**代价**：单次生成成本约为原方案的 3–4 倍【假设，P0 实测】；等待是分钟级；AI 写的代码要在玩家设备上运行，必须靠沙箱和发布检查约束（[architecture.md](architecture.md) 第 5 节）。

**实现要点**
- 项目结构固定：规则在 `src/sim/`（确定性），画面在 `src/view/`，可调数值和文案集中在 `game.config.json`。小改先判断能否只改配置，能就不动代码。
- **游戏规则必须是确定性的**：`src/sim/` 只能用共享运行时提供的时间、随机数和数学工具，由 lint 强制。服务端用这款游戏自己的 sim 代码在隔离环境里回放（第 4.7 节）。
- 发布前：构建 → 静态检查（禁止网络请求、`eval` 等）→ 无头冒烟测试 → 回放自检 → 内容安全 → 审核。失败时 agent 自动修复，最多两次，仍失败则退还点数。
- 运行时：独立域名、沙箱 iframe、CSP 禁止任何外连，游戏拿不到凭证。

**首发模板**【已确定，五个】，按开发顺序：
1. **Idle Clicker / Incremental**：点击 → 自动产出 → 升级 → 转生。规则最固定，先做。
2. **Idle RPG / Cultivation**：挂机修炼、境界突破、装备、离线收益；修仙是主打主题之一。
3. **Tycoon / Shop Manager**：经营一家店（咖啡馆、花店、农场），顾客、扩建、雇员。
4. **Merge 合成类**：拖动合成升级物品；交互最复杂，放最后。
5. **互动故事**：分支剧情、选项、多结局；每个场景可以配插图、背景音乐、配音和短视频过场。没有分数，不进排行榜。移植 ohmygame 的互动故事运行时，可以和 Merge 并行开发。

五个模板共用同一个共享运行时。

**起步工程**：模板之外的玩法从 2D 起步工程（Phaser）或 3D 起步工程（three.js）开始，首发对所有档位开放，按 Seeds 计费，价格高于模板（没有模板打底，轮数和失败率更高）。3D 游戏都从 3D 起步工程开始。

## 3.1 视觉风格【已确定方向】

- **预置画风**：平台提供几套经过调校的画风（候选：cozy 手绘、像素、扁平卡通、水墨/仙侠），每套有固定的风格提示词、配色和参考图，保证同一款游戏内的素材风格一致。
- **自由风格**：用户也可以用一句话描述自己的画风（"像儿童蜡笔画""赛博朋克霓虹"）。
- 自由风格的处理：
  - 先生成一张风格样张让用户确认，再批量生成素材，避免整套返工。
  - 风格描述同样过 IP 与内容安全检查（拦截"像某知名游戏/动画的画风"这类请求）。
  - 自由风格的素材一致性更难保证，可能需要更多生成次数——点数消耗可高于预置画风【假设，需实测】。
- 平台界面本身保持统一的品牌风格，不随游戏画风变化。

## 4. 核心循环

### 4.1 玩（所有用户）
打开链接 → 首屏直接进游戏（游客，无需注册）→ 30 秒内看到第一次升级 → 离开 → 存档保留、离线收益累积 → 回来领取 → 想上榜/跨设备时再登录。

### 4.2 改（转化入口）
在任何游戏里点 **"Make my version"** → 一句话描述改动（"换成我家的橘猫""升级快一倍"）或点选项卡片 → 几秒到几十秒出结果 → 试玩 → 满意就发布。
- 免费用户每周有少量改编额度，作为订阅的"试吃"。

### 4.3 做：从 0 到 1（核心付费）

从题材模板或 2D / 3D 起步工程做一款全新游戏。面向小白，每一步都有「让 AI 帮我定」，也可以自己改；每步自动存草稿，可以随时回到上一步。

| 步骤 | 用户做什么 | AI 做什么 |
|---|---|---|
| 1. 起点 | 一句话描述想做的游戏，或直接选模板 | 推荐最合适的模板；描述超出 5 个模板时，建议从 2D 或 3D 起步工程做，并说明成本更高、成功率更低 |
| 2. 设定卡 | 确认或修改名字、主题、主角、核心资源、目标 | 生成设定卡（免费、限频） |
| 3. 玩法系统 | 在模板提供的模块里勾选和调整，也可以用一句话提出模板没有的玩法（例：放置类的生产建筑、升级、转生、随机事件；经营类的顾客类型、菜单、扩建、雇员） | 按设定卡给出默认组合 |
| 4. 节奏与数值 | 选节奏（快 / 中 / 慢）和目标游玩时长 | 把数值写进 `game.config.json`，并跑模板自带的可解性检查（不卡死、能转生、收支能转正） |
| 5. 美术 | 选预置画风或描述自由画风 → 确认样张 → 确认关键素材（主角、主物件、合成链第 1 级） | 先生成关键素材，再从它们派生出整套系列（见 4.3.1） |
| 6. 内容 | 修改文案、事件、成就 | 生成多语言文案和事件 |
| 7. 试玩与修改 | 试玩，用对话修改 | 能只改配置就只改配置；否则 agent 改代码、自己试玩后再交给用户 |
| 8. 发布 | 发布到 Pocketgrove，或导出到 CrazyGames（4.6 节） | 发布前自测，并生成商店描述和封面 |

- 计费：第 2–4 步只生成文字和数值，不进容器，成本低；第 5 步起 agent 会话和整套美术是成本大头。点数怎么拆分、各操作多少点，在 P0 实测 agent 成本后重定（[architecture.md](architecture.md) 第 8 节）。
- 「从零做」和「改编」共用同一套编辑器：改编就是从一款现有游戏的第 7 步开始。

### 4.3.1 创作画板（借鉴 ohmygame 的画布理念）

8 步引导是「怎么一步步做」，画板是「做出来的东西放在哪、怎么继续改」。两者编辑的是同一个项目，随时可以切换。

**项目里有什么**：画板上的每个节点都是项目的一部分——设定卡、玩法模块、数值曲线、美术素材、文案和事件。画板只是项目文件（`game.config.json`、`assets.json`、源码）加素材库的另一种看法；agent 和画板编辑的是同一批文件（ohmygame 的做法）。

**三条核心规则**
1. **素材可以派生**：任何一张素材都能「派生出更多」——一张主角草图派生出开心、升级、第三境界等形态；合成链第 1 级派生出第 2–8 级；一套顾客派生出新的顾客类型。派生时自动把父素材作为参考图（加上同一套画风的风格 ID / 参考图），保证系列一致。
2. **每个素材绑定到游戏里的一个位置**：例如「合成链 A 第 3 级」「顾客类型 2」「主角 · 境界 3」。替换或重画一张，游戏里立即生效，不需要导出、上传或对位。没有绑定位置的素材留在画板上做备选，不进发布包。
3. **保留来历**：每个素材记录父素材、提示词、画风、厂商和版本。可以回退到旧版本；改编别人的作品时，来历一并保留（用于署名和换皮判断）。

**两种视图**
| | 手机：树状视图（MVP） | 电脑：画板视图（MVP 之后） |
|---|---|---|
| 形态 | 按「设定 → 系统 → 美术 → 内容」分组的卡片列表；派生关系展开成树 | 无限画板，节点可拖拽、并排比较、连线表示派生关系 |
| 适合 | 小白、碎片时间、按引导一步步做 | 想精细打磨、批量对比素材的创作者 |
| 操作 | 点卡片 → 「派生出更多」「重画」「换成这张」 | 同左，另加多选批量派生、框选对比 |

**素材类型的范围**（首发全部接入，厂商见 [media-models.md](media-models.md)）
- **2D 图片**：图标、物品、角色、场景、UI 底图，所有模板都用得上。
- **3D 模型**：3D 游戏的角色、道具、场景件。角色可以继续「派生」出绑骨版本和动画（待机、行走、攻击），派生关系在画板上显示成树；绑定位置例如「主角 · 行走动画」。
- **音频**：音效、背景音乐、配音。配音只用预置音色，不做声音克隆。模板自带的音效包仍然是免费的默认声音，AI 音频是可选的升级。
- **视频**：互动故事的过场、片头、动态背景，单段最长 10 秒；也可以做宣传短片。
- **宣传视频仍然默认用无头浏览器录制**真实游玩画面（几乎零成本）；AI 视频是用户主动选择的付费操作。
- 所有媒体素材都遵守三条核心规则：可以派生、绑定到游戏位置、保留来历。

**计费**
- 派生一张或重画一张：2 Seeds（与「重绘单张」同价），平台原因的失败退点。
- 3D、音频、视频按 [pricing.md](pricing.md) 的媒体操作价格计费，开始前显示价格。
- 批量派生（例如一次补齐整条合成链）按张数计，开始前显示总价。
- 用户只为不满意的那张付钱，不需要整套重来——这也让从零生成的成本更可控。

**和其他设计的关系**
- **一致性**：Merge 合成链、修仙境界、同一角色多状态，原来最难保证，改为「先定父素材、再派生」后有了明确做法。美术比稿要专门测「从父图派生」的一致性。
- **CrazyGames 换皮风险**：用户在画板上逐张改出自己的素材，差异度自然更高；素材来历也能用来判断作品与原作的差异。
- **实现参考**：ohmygame（Apache-2.0）的画板和素材画布共用一套 JSON 节点模型；我们移植这套节点模型（保留图片、3D、音频、视频节点，补上素材版本），见 [ohmygame-review.md](ohmygame-review.md)（见 [open-source-references.md](open-source-references.md)）。只借鉴设计和代码，名称和 logo 不在其许可范围内。

### 4.4 分享（增长）
- 每款游戏一个短链接 + 分享卡片（游戏截图、作者、"Beat my score"）。
- 作品页显示"Made with Pocketgrove"，玩家点进来就是"Make my version"。
- 挑战链接：好友打开后打的是和你**同一个种子**的挑战局，结束时直接对比分数（第 4.7 节）。

### 4.5 付费
- 撞到额度墙（改编次数、生成次数、高级画风）→ 订阅页。
- 游戏内激励广告：复活、加倍离线收益、跳过等待——玩家自愿观看。

### 4.6 分发：Pocketgrove + CrazyGames

同一款游戏有两个发布目标，游戏通过共享运行时里的一层**平台适配器**对接，不为每个平台单独改游戏：

| 能力 | Pocketgrove 上运行 | CrazyGames 导出包 |
|---|---|---|
| 平台接口 | `pocketgrove-sdk` | CrazyGames HTML5 SDK 适配器 |
| 存档 | 通过 SDK 桥接：游客匿名云存档，登录后并入账号（第 4.7 节） | CrazyGames 的数据/存档模块 |
| 广告 | Pocketgrove 的激励广告位 | **只能用 CrazyGames SDK 的广告**（Full Launch 规则） |
| 登录 / 排行榜 / 分享 | Pocketgrove 账号、排行榜、挑战链接 | 全部去掉（Basic Launch 不允许外部登录） |
| 游戏开始 / 结束事件 | 平台统计 | 必须上报 `GameplayStart`（Full Launch 必需） |
| 署名 | 「Made with Pocketgrove」可点击 | 是否允许外链待核实；先只在加载页放不可点击的文字署名 |

**CrazyGames 导出流程**（限 Plus / Pro）
1. 用户在作品页点「导出到 CrazyGames」。
2. 平台先跑导出前检查：英文文案完整、PEGI 12 内容分级、不是面向儿童的内容、不是 IP 仿冒；与平台上已有作品的差异度足够（见下方风险）；在 4GB 内存的 Chromebook 等级设备上运行流畅。
3. 生成导出包：单个 HTML（远低于 50MB 首包 / 250MB 总量 / 1,500 个文件的限制），已接好 CrazyGames SDK，Basic Launch 可直接上，被选中 Full Launch 时无需重做。
4. 同时生成上架素材：英文描述、操作说明、多尺寸封面图、一段由无头浏览器录制的试玩视频。
5. 用户在**自己的** CrazyGames 开发者后台提交（先完成对方的收款认证），广告分成直接归用户；Pocketgrove 不经手收款和税务。
6. 修改后重新导出新版本，由用户自己更新。

**风险与待核实**
- **素材换皮（asset flip）会被拒**：CrazyGames 会拒绝克隆和换皮游戏。同一模板上只换主题的改编很可能被判为换皮，所以导出前检查要限制差异度不足的作品；从零做的作品通过率更高。这也是 4.3 节要把「从零做」做好的原因之一。
- **授权**：用户协议要写清，用户可以在导出包里再分发我们的共享运行时和模板代码；所用图像厂商的付费商用授权也要覆盖「用户在第三方平台再分发」。
- **欧盟 AI 法案第 50 条**（2026-08-02 起生效）：在欧盟分发的 AI 生成图像需要机器可读的标识。Pocketgrove 首发不含欧盟，但 CrazyGames 面向全球，导出包需要带上 AI 生成标识。
- CrazyGames 没有官方的 AI 内容政策（第三方 2026 年秋核实），也没查到公开的自动提交接口；分成比例未公开。上线前以开发者文档为准。

### 4.7 存档、离线收益与排行榜

游戏跑在不带 `allow-same-origin` 的沙箱 iframe 里，拿不到 `localStorage` 和 cookie，也拿不到登录凭证。所以存档、时间、分数都交给外层的平台页面处理，游戏只通过适配器发请求。

#### 存档

| 项 | 设计 |
|---|---|
| 接口 | 游戏通过共享运行时调用 `save.load()` / `save.write()`；Pocketgrove 上经 postMessage 交给外层页面，CrazyGames 导出包走对方 SDK 的存档模块 |
| 游客 | **匿名云存档**：外层页面在主站域名下生成一个随机设备 ID，存档按「设备 ID + gameId」写到服务器，本机再留一份缓存（离线时可用、联网后同步） |
| 登录用户 | 存档归属账号；第一次登录时把该设备的匿名存档并入账号，之后设备 ID 不再用于存档 |
| 内容 | 只存游戏状态，用稳定 ID 引用（例：建筑 `bakery_oven` 等级 12），带运行时版本、sim 版本和 `gameVersion`。作者改数值后旧存档照常可用；被删除的物品读档时丢弃 |
| 体积与频率 | 每款游戏 ≤ 64KB；每 10 秒自动存一次，页面进后台或关闭时再存一次 |
| 改编 | 改编作品是新的 gameId，存档与原作独立 |
| 多设备冲突 | 按服务器时间以最后一次写入为准；两边进度差距大时弹窗让用户选保留哪份 |

**匿名设备 ID 的边界**（因为它属于持久标识，需要守住用途）
- 只用于存档和同步：不用于广告个性化、不做用户画像、不与第三方共享、不和任何其他标识关联。
- 游客期间不展示个性化广告。
- 长期不活跃（例如 180 天）自动删除对应存档。
- 隐私政策里写明。
- 合规依据需要律师确认：美国 COPPA 对「仅用于支持内部运营」的持久标识有例外；英国 PECR/GDPR 下，为提供用户请求的服务所必需的存储可以不弹同意框。确认之前，不要把这个 ID 用作任何其他用途。
- 设备 ID 仍可能因内置浏览器（TikTok、Instagram）或 Safari 清理存储而丢失，丢了就找不回存档。所以游客玩出一定进度后（例如第一次转生）仍提示「登录保存进度」，在内置浏览器里额外提示「在浏览器中打开」。

#### 离线收益

- 时间不信任客户端：外层页面从平台的时间接口取服务器时间交给游戏。
- 离线收益 = min(服务器当前时间 − 上次存档的服务器时间, **8 小时**)；看一次激励广告可以翻倍。
- 没联网时不发离线收益，联网后补发。
- 设了上限并按服务器时间计算后，改设备时钟不能多拿收益。

#### 排行榜

两种榜，都要求登录才能上榜。互动故事没有分数，不进这两种榜；它的分享卡是「我走到了结局 3 / 5」，挑战链接是「看看你会走到哪个结局」。

| | 挑战局榜 | 赛季进度榜 |
|---|---|---|
| 比什么 | 每个模板一种 3–5 分钟的短局，固定种子、固定开局。例：Tycoon「5 分钟一个班次的营业额」、Merge「最快合出第 6 级」、Idle 和修仙「最快达到第一次转生 / 某个境界」 | 每周一个赛季，赛季开始时开一份**全新的赛季存档**，比本周达到的最高阶段（每个模板定义阶段指标）。和玩家的常规存档分开 |
| 节奏 | 每日挑战（全球同一种子）；分享出去的挑战链接用同一种子 | 每周重置 |
| 激励广告 | 不可用 | 不可用（赛季里离线收益只用基础的 8 小时上限，不能翻倍） |
| 校验 | 提交整局操作记录 | 每次存档时增量上传操作记录和状态检查点 |

**校验**
- **只有通过回放自检的游戏才开放公开排行榜和赛季**：发布时用机器人跑几局，浏览器和服务端隔离环境的结果一致才算通过。没通过的游戏照常能玩、能分享，挑战链接里的好友比分标明「未校验」。
- 所有提交都做合理性检查：增长速度不超过该游戏在当前配置下的理论上限，点击频率不超过人类上限（例如每秒 15 次），时间线和服务器记录一致。
- **会进入前 100 名的提交，在服务端隔离环境里用这款游戏自己的 sim 代码回放重算**；结果不一致的不上榜并记录。赛季榜从最近一个已校验的检查点开始回放，不必每次从头。
- 回放挡得住改分数，挡不住机器人完美操作；后者靠合理性限制、举报和人工复核。
- 分数由外层页面带着用户会话提交，游戏本身拿不到任何凭证。
- 作者发布了改变数值的新版本时，排行榜按版本分开，作者不能靠改数值把自己刷上榜。
- 游客也能打挑战局：结束时显示「你能排第 N 名，登录领取」，操作记录先存着，登录后提交校验。
- CrazyGames 导出包没有 Pocketgrove 排行榜（见 4.6 节）。

### 4.8 激励广告

- **广告不进游戏沙箱**：游戏通过 SDK 调用 `ads.requestRewarded(原因)`，由外层平台页面播放广告；播完后外层页面通知游戏发奖励。广告代码和第三方脚本都不在游戏 iframe 里运行。
- **多家广告抽象层**：外层页面按顺序尝试多个广告来源。首选 Google H5 游戏广告（Ad Placement API，AdSense 或 Ad Manager）。它目前是封闭测试，需要已通过审核的 AdSense 账号，网站上还要有可玩的 HTML5 游戏，所以**只能在上线后申请**。游戏站广告网络（如 Playwire、Venatus）通常有流量门槛，等流量起来再评估。
- **没有付费广告可播时**（上线初期、申请中、或某次无填充）：
  - **游戏内奖励**（离线收益翻倍、复活、跳过等待）照常发放，播一条自家广告（推荐 Plus 或其他游戏）代替。这类奖励对平台没有成本。
  - **Seeds 奖励**只在真正播完一条付费广告后才发（每次 1 Seed、每天最多 3 次，见 [pricing.md](pricing.md)），因为 Seeds 是真实的模型成本。
- **合规与政策**：
  - 奖励按钮必须写清看完能得到什么，由用户主动选择观看（Google 激励广告政策）。
  - 英国用户需要 Google 认证的同意管理工具（CMP）。
  - 游客不投个性化广告（见 4.7 节设备 ID 的边界），只投非个性化广告，单价会更低。
  - 挑战局和赛季榜里不能用广告加成（见 4.7 节）。
- **CrazyGames 导出包**：只用 CrazyGames SDK 的广告（见 4.6 节），不经过这一层。
- **对收入预期的影响**：上线初期没有付费广告收入，免费档成本由市场推广预算承担（见 [pricing.md](pricing.md) 4.2 节）。

### 4.9 冷启动内容

首发只有 5 个模板，如果每个只有 3–5 款，信息流会显得空。三件事一起做：

1. **自营约 50 款**：每个模板约 10 款，另做几款 3D 游戏作为 3D 起步工程的示范，用我们自己的生成器做（同时暴露生成器的问题），少数旗舰款用 studio / ohmygame 精修。生成成本每款约 $2.5–4【假设，P0 实测】，瓶颈是人工打磨时间。
2. **封闭创作者内测**：公开上线前 4–6 周，邀请 50–100 名创作者免费使用 Pro。
   - 从放置、经营类游戏的 Reddit 和 Discord 社区里招募；这些人本身就是目标用户。
   - 模型成本最多约 $1,100/月（100 人 × 550 Seeds × $0.02），计入推广预算。
   - 目标：上线时有 150–300 款经过精选的 UGC；同时拿到第一批真实的点数使用率、生成成功率和成本数据，用来校准定价。
   - 内测作品照常审核，不合格的不进信息流。
3. **首页不靠数量取胜**：首页以「今日挑战」和本周赛季为中心，每日挑战每天轮换一款游戏；每款游戏的页面下列出它的改编版本。对外强调「每款都能玩好几周」，不和 Astrocade 拼数量。

| 档位 | 价格 | 点数 |
|---|---|---|
| Free | $0 | 每周 20 Seeds（约 1 次改编或 4 次小改），不累积；看付费广告每次 +1 Seed，每天最多 3 次 |
| Plus | $7.99/月（年付 $79） | 每月 200 Seeds；自由画风、去水印、优先队列 |
| Pro | $19.99/月（年付 $199） | 每月 550 Seeds；最高优先、草稿不限 |

- 操作定价（旧估算，按题材引擎方案算的，**转向编码 agent 后需重算**）：设定卡免费、小改 5、重绘或派生单张 2、改编 20、从零生成 50 Seeds；平台原因的失败全额退还。agent 方案下从零生成的成本约为原估算的 3–4 倍（[architecture.md](architecture.md) 第 8 节）。
- 3D、音频、视频等媒体操作对所有档位开放，按 Seeds 单独计费（估算价见 [pricing.md](pricing.md) 第 3.1 节）；单次操作设上限，例如视频单段最长 10 秒。
- 点数包不过期：100 Seeds $4.99、300 Seeds $12.99。
- 美国、加拿大按美元标价另加税；英国、澳大利亚按本地币含税价，点数不变（测算见 [pricing.md](pricing.md) 4.1 节）。
- 创作者奖励先发 Seeds（每 1,000 次游玩 10 Seeds、精选 100 Seeds），现金分成后置。
- 定价原则：档位用满时模型成本 ≤ 约 50% 收入，平均用户 ≤ 30%；具体数字在 P4 实测后调整。

## 7. 指标

- **北极星**：每周回访玩家数（7 日内回来玩过至少 2 天的玩家）——直接对应"题材专精 → 重复游玩"的假设。
- 漏斗：首屏进游戏率 → 30 秒留存 → 次日回访 → 点"Make my version" → 发布 → 订阅。
- 成本：每次改编 / 生成的平均模型成本；订阅用户的成本占收入比。
- 内容：生成成功率（自测通过率）、审核通过率、每款 UGC 的平均游玩次数。

## 8. 设计原则

1. **3 秒可玩**：任何链接打开后 3 秒内能操作。
2. **先玩后登录**：任何时候都不强制注册才能玩。
3. **改比做简单**：改编是默认入口，从零生成是进阶。
4. **质量下限由模板和共享运行时保证**：存档、离线收益、广告、适配这些容易出错的部分由我们写好、agent 不能改；发布前必须通过冒烟测试。
5. **不打扰的广告**：只做玩家主动选择的激励广告，不做插屏。
6. **只做原创**：拦截知名 IP，作品可举报、可下架。
