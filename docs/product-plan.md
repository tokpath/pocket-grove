## 1. 定位

**一句话**：面向碎片时间小白用户的 H5 小游戏站——能玩，也能用一句话做出自己的游戏并分享出去。先上海外版，英文优先、支持中文，点链接即玩。

**两条腿**
1. **玩**：自营精品游戏 + 优质 UGC，打开链接就能玩。
2. **做**：平台内置 AI 游戏生成器，订阅制，生成结果直接成为可分享、可上榜的游戏。

**不做什么**
- 不做中重度游戏、不做需要下载的 App 分发。
- 不复刻任何现有游戏，只做原创玩法与美术；生成器也要拦截"做一个 XX 游戏（某知名作品）"类请求。

**和同类（TapTap 制造、造化工坊、星匣、K399、233 工坊）的差异**
| 我们 | 同类 |
|---|---|
| 生成结果是开放网页，任何社交 App 或浏览器里点链接即玩 | 多数只能在自家 App/引擎内运行 |
| 面向完全不懂开发的小白：一句话 + 选项式调整，不需要本地工具 | 进阶创作者逐步转向本地开发 + 自带模型 |
| 自营精品打底，冷启动有内容 | 以 UGC 为主，质量参差 |
| 海外优先，中英双语 | 以国内为主 |

## 2. 产品形态

- 一个响应式 Web 服务（Next.js），手机竖屏优先；电脑端把游戏放在居中的手机比例框里，两侧显示排行榜和游戏信息。
- 页面：发现页（卡片流/题材/榜单）、游戏详情（介绍/排行榜/「做我的版本」）、游玩页（独立域名沙箱 iframe）、排行榜、个人页、**生成器**、**我的作品**、**订阅与额度**。评分、评论、点赞在 MVP 之后加入（与 [prd.md](prd.md) 第 5 节一致）。
- 账号：游客即玩；上榜/生成/发布时登录（Google、Apple、邮箱魔法链接）。
- 语言：英文默认，按浏览器语言自动切换中文；生成器支持用户用任一语言描述游戏，游戏内文案跟随用户语言。
- 分享是第一拉新渠道：每款游戏有分享卡片（Open Graph / Twitter Card）和"挑战我的分数"链接，适配 TikTok、Discord、Reddit、WhatsApp、X 的链接预览；UGC 作品的分享页标明"Made with Pocketgrove"，引导"我也做一个"。
- 自营游戏可额外投放到 itch.io 等 H5 游戏门户，作为外部引流（各门户的独占与 SDK 条款需逐一确认）。
- 用户作品（Plus / Pro）可一键导出为符合 CrazyGames 要求的游戏包 + 上架素材，由用户用自己的 CrazyGames 账号提交，广告分成归用户（见 [prd.md](prd.md) 4.6 节）。

## 3. 内容供给

### 3.1 自营游戏（冷启动 + 质量标杆）
- **生成器优先**：自营游戏优先用我们自己的生成器制作（自己当第一个用户），生成器的质量问题由此最先暴露。
- 题材：按首发的 5 个题材模板制作——Idle Clicker、Idle RPG / Cultivation、Tycoon、Merge、互动故事（每个模板约 10 款，共约 50 款），另做几款 3D 游戏作为 3D 起步工程的示范。
- 公开上线前 4–6 周做封闭创作者内测：邀请 50–100 名创作者免费用 Pro，目标上线时有 150–300 款精选 UGC（见 [prd.md](prd.md) 4.9 节）。
- 自营游戏同时作为生成器的"模板库"和"改编起点"。

### 3.1.1 `studio/`：参考与精修工具（不在关键路径上）
- 从 [Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios)（MIT）clone 的独立 git 仓库，保留 `template` remote，需要时 `git merge template/main` 升级。
- 用途一：**生成器的设计输入**——借鉴 `/prototype` 的一次成型流程（问一轮 → brief → 生成 → 无头自测 → 状态卡 → 对话修改 → 检查点）、`config.js` 集中数值的约定、`.claude/genres/` 题材资料与 `game-brief` 模板、无头自测/截图脚本思路。借鉴与改写保留 MIT 署名。
- 用途二：**旗舰游戏精修**——少数重点游戏由内部在本地用它打磨，`project.yaml` 保持 `modes.rigor: minimal`。
- 不使用：工作室模式（49 个 agent、GDD/ADR/冲刺/阶段评审）、Godot/Unity/Unreal 路线、Steam 发布流程。
- [ohmygame](https://github.com/WhiteTowerAI/ohmygame) 是生成后端的**模块来源**：agent 运行时用它底层的 Pi SDK，并移植它的试玩工具、画板模型和检查点（见 [architecture.md](architecture.md) 第 7 节、[ohmygame-review.md](ohmygame-review.md)），同时也可以本地运行来打磨模板和旗舰游戏。
- 不再为它单独开发对接件（原计划的 `/spark-publish`、`spark-platform` 规则取消）；精修后的游戏走与 UGC 相同的发布管线。

### 3.2 AI 游戏生成器（核心功能）

**用户流程**
1. 输入一句话（可选题材、画风、操作方式等选项卡片）。
2. 平台先生成一页 brief（玩法、目标、操作、胜负条件）让用户确认——便宜、快，避免整款重做。
3. 生成可玩游戏，流式展示进度；完成后自动做构建、静态检查和无头自测，不通过时自动修复，最多两次；仍不通过则告知用户并退还点数。
4. 预览试玩 → 对话式修改（"再难一点""换成猫咪"）→ 保存版本。
5. 发布：进入审核队列，通过后上架，可分享、可上榜。

**两种生成方式**
- **从零生成（0 到 1）**：从题材模板（或 2D / 3D 起步工程）分步引导——起点 → 设定卡 → 玩法系统 → 节奏与数值 → 美术 → 内容 → 试玩修改 → 发布（详见 [prd.md](prd.md) 4.3 节）。
- **改编**：复制平台已有游戏（自营或公开授权的 UGC）的项目，由 agent 换主题、改数值、换皮肤——比从零生成便宜、成功率更高，作为默认推荐入口之一。

**技术要点**（详见 [architecture.md](architecture.md)）
- 生成只在平台服务端调用模型，用户不能接入自己的模型或 Key；Key 只在容器外的模型网关里。
- **编码 agent + 题材模板**：基于 Pi SDK 的编码 agent（移植 ohmygame 的试玩工具和画板模型），在每个会话独立的容器里改模板代码（TypeScript；2D 用 Phaser，3D 用 three.js），自己构建、试玩（无头 Chromium）、修复。
- **媒体**：图片、3D 模型（含绑骨和动画）、音效、音乐、配音（预置音色）、短视频首发都接入，走服务端媒体路由（[media-models.md](media-models.md)）。
- 项目结构固定：规则在确定性的 `src/sim/`，画面在 `src/view/`，可调数值和文案集中在 `game.config.json`（借鉴 studio 的 `config.js` 约定）。小改能只改配置就不动代码，成本低一个量级。
- 共享运行时（存档、时间、离线收益、广告、挑战局、平台适配器）由我们写好并锁定，agent 不能改。
- AI 写的代码会在玩家设备上运行：发布前做静态检查（禁止网络请求、`eval` 等）和无头冒烟测试；运行时在独立域名的沙箱 iframe 里，CSP 禁止任何外连，与主站完全隔离。
- prompt 素材复用 studio 模板里的题材资料和 brief 模板（MIT，保留署名）。
- 服务端自测：无头浏览器加载、检查报错、检查 SDK 握手、回放自检、截图做封面。

**成本控制（平台承担全部模型成本，必须设计在先）**
- 每次生成前按操作类型扣"生成点数"：brief < 小改 < 改编 < 从零生成。
- 自动修复、平台原因导致的失败不扣点。
- 系统提示词与游戏模板走提示词缓存。
- 修改走增量编辑，不整款重写。
- 单用户并发与每日上限、异常行为风控。
- 上线前先实测每类操作的真实 token 消耗，再定点数和价格（见第 6 节）。

**审核与安全**
- 上架前：自动检查（内容安全、外链/外部请求、体积、原创性/侵权关键词）+ 人工抽检。
- 平台承担审核责任，协议里写清创作者与平台的权责，不把内容安全责任全部推给创作者。
- 按法规要求对 AI 生成内容做标识。

## 4. 游戏包契约（自营、UGC 共用的唯一接口）

```
games/<gameId>/<gameVersion>/
  index.html        构建产物入口；Phaser / three.js 和共享运行时按固定哈希从沙箱域名加载（所有游戏共享缓存）
  game.js           这款游戏的构建产物（src/view + src/sim）
  sim.js            单独构建的规则模块，服务端回放用
  game.config.json  可调数值和文案（zh/en）
  assets/           素材：图片、GLB 模型、音频、视频（文件名为内容哈希）+ assets.json（素材位 → 文件）
  cover.png         封面
  manifest.json     id、模板 + 模板版本、运行时版本、标题(zh/en)、简介(zh/en)、横竖屏、分数方向(asc/desc)、版本、
                    sim 哈希、是否通过回放自检、来源（模板、改编自哪款、生成会话 id）
```
- 游戏的源码仓库（项目工作区）保存在平台，改编时复制；游戏包是它的构建产物。导出 CrazyGames 时另打一份单 HTML。
- 平台通过 pocketgrove-sdk 与游戏通信（postMessage + MessageChannel，协议见 [p1-contract.md](p1-contract.md) 第 6 节）：ready、存档读写（`save.load` / `save.write`）、服务器时间、挑战局开始与结束（种子下发、操作记录与分数提交）、游戏结束、激励广告位请求。存档、时间、分数都由外层平台页面处理，游戏拿不到任何凭证（见 [prd.md](prd.md) 4.7 节）。
- 游戏只调用共享运行时里的**平台适配器**接口；发布到 Pocketgrove 时接 pocketgrove-sdk，导出 CrazyGames 时接 CrazyGames HTML5 SDK（存档、广告、`GameplayStart` 走对方 SDK，去掉 Pocketgrove 的登录、排行榜和外链）。同一份源码打两种包。
- 游戏放在与主站隔离的独立域名下，iframe sandbox 运行。

## 5. 架构

```
pocket-grove/
  studio/     参考与精修工具（模板 clone，独立 git 仓库，父目录 ignore）
  platform/   Next.js 平台（含生成器前端与 API）
  sdk/        pocketgrove-sdk.js
  games/      已上架的游戏包
  scripts/    publish-game：导出 → 校验 → 注入 SDK → 生成 manifest → 入库
  docs/       方案文档
```
- 数据：SQLite 起步，之后迁移 Postgres；生成任务需要队列（排队、重试、超时、扣点/退点）。
- 模型：Claude API，默认 `claude-opus-5-5`，流式输出；处理 `refusal` 停止原因并启用服务端 fallback。分档使用其他模型属于产品决定，需在实测成本后再定。
- 生成：我们自己的精简生成服务（Pi SDK）跑在生成 worker 上，每个 agent 会话一个隔离容器（候选 gVisor 或 Firecracker），内含项目工作区和无头 Chromium；模型、图像、3D、音频、视频厂商的 Key 只在容器外的模型网关里，网关负责计量和限额。
- 回放：服务端在 V8 隔离环境（如 `isolated-vm`）里运行每款游戏自己的 `sim.js`。
- 部署：Vercel 或 Cloudflare（平台），游戏包放独立域名的对象存储 + CDN；生成 worker 单独部署（需要容器编排和无头浏览器，Vercel 函数不适合）。
- 支付：Stripe（订阅 + 点数包，含税费处理）。

## 6. 商业化（详见 [pricing.md](pricing.md)）

1. **AI 订阅（核心）**：点数单位为 Seeds。Free 每周 20 Seeds（不累积）；Plus $7.99/月，每月 200 Seeds；Pro $19.99/月，每月 550 Seeds。另有不过期的点数包（100 Seeds $4.99、300 Seeds $12.99）。通过 Stripe 收费。CrazyGames 导出限 Plus / Pro。3D、音频、视频等媒体操作对所有档位开放，按 Seeds 单独计费。
2. **激励广告（IAA）**：复活、加倍奖励、每日签到；免费用户看完一条付费广告换 1 Seed（每天最多 3 次）。广告由外层平台页面播放，做多家抽象层；Google H5 游戏广告（Ad Placement API）是封闭测试，上线后再申请。没有付费广告时，游戏内奖励用自家广告兜底照常发，Seeds 不发（见 [prd.md](prd.md) 4.8 节）。上线初期免费档成本计入推广预算。
   - 英国、澳大利亚按本地币含税价定价，美国、加拿大美元另加税（见 [pricing.md](pricing.md) 4.1 节）。
3. **轻内购（IAP）**：皮肤、称号等，后做。
4. **创作者激励**：先发 Seeds——作品每被玩 1,000 次得 10 Seeds、进精选得 100 Seeds；现金分成等有广告收入数据后再定。导出到 CrazyGames 的作品，广告收入直接归用户。

**单位成本参考（待 P0 实测）**：转向编码 agent 后，一次从模板做新游戏约 $2.5–4——其中 agent 会话（Claude Opus 5.5，约 30 轮工具调用）约 $2–3，整套美术约 $0.65。改编约 $1–2，只改配置的小改约 $0.15–0.4。这是旧估算（$0.95）的 3–4 倍，现有点数定价要在 P0 实测后重算（见 [architecture.md](architecture.md) 第 8 节）。从 3D 起步工程做一款约 $6–12；3D、音频、视频素材另按单次计费（[media-models.md](media-models.md)）。

## 8. 风险

海外版（当前）：
1. **成本倒挂**：平台承担全部模型成本，定价前必须有实测数据；免费档要严格限量，防止批量注册薅点数。转向编码 agent 后单次生成成本约为原估算的 3–4 倍，这是现在最大的风险（[architecture.md](architecture.md) 第 8、10 节）。
   - **AI 代码在玩家设备上运行**：靠容器隔离、依赖白名单、静态检查、冒烟测试、沙箱 iframe 和 CSP 禁止外连层层约束；仍要有举报和快速下架。
   - **媒体成本与 3D 性能**：视频按秒计费，3D 角色要生成、绑骨、做动画；3D 游戏在低端手机和内置浏览器里更容易卡。靠开始前显示价格、单次上限、设备分级和体积预算兜底（[architecture.md](architecture.md) 第 9、10 节）。
   - **媒体合规**：首发不做声音克隆，只用预置音色；视频和 3D 同样禁止真人照片作参考；各厂商的商用和再分发条款签约前逐家确认（[media-models.md](media-models.md) 第 3 节）。
   - **依赖 Pi**：Pi 迭代快、社区比官方 SDK 小；锁定版本，只通过会话装配那一层使用，必要时可换成 Claude Agent SDK。
2. **隐私与广告合规**：欧盟/英国用户需要 GDPR 同意弹窗（广告个性化必须征得同意），加州有 CCPA；需要隐私政策与用户协议。
3. **未成年人**：小游戏天然吸引儿童。已定的门槛是：游玩不限；登录、生成、发布、付费需 18+。游客有一个匿名设备 ID 用于云存档，它属于持久标识，只能用于存档，不能用于广告个性化或画像；依据 COPPA「内部运营」例外和英国 PECR「严格必要」存储的判断需要律师确认（见 [prd.md](prd.md) 4.7 节）。不做面向儿童的内容（CrazyGames 也会拒绝）。
4. **UGC 内容安全与侵权**：审核能力要跟上生成量；需要 DMCA 下架流程和举报入口；拦截仿冒知名游戏/IP 的生成请求。
5. **模型使用政策**：生成器的用途与内容需符合 Anthropic 的使用政策。

国内版（延后）：
- Anthropic 不向中国大陆提供服务，国内版需接入已备案的国产模型；面向公众的生成式 AI 服务需备案并对生成内容做标识。
- 订阅收费需要相应的经营性许可；带广告/内购的游戏涉及软著与版号。
- 架构上把"模型调用"做成可替换的一层，为国内版换模型留口子。
